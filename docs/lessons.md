# 十条弯路

这些都是做工作台时真实踩过的坑。每条给出“症状 → 为什么错 → 正确做法”。

## 1. 按内容分类加 Tab

**症状**：一开始是“今日 / 政策 / 解读 / 申报 / 竞品 / 报告”，半年后 9 个 Tab，每个都点不完。

**为什么错**：Tab 是“我现在要做什么”的模式，不是“这类东西放哪”的目录。分类会膨胀，模式不会。

**正确做法**：Tab 固定为 今日 / 资料库 / 报告 / 设置。分类放进第二行 chip；层级放第一行 chip。新增分类时先问：它是不是一种新的工作方式？不是就别加 Tab。

## 2. 左树 + 右详情

**症状**：在 400px 侧栏里，左边 160px 的树，右边标题只能显示 8 个字；一打开详情，两边都挤。

**为什么错**：窄栏的宽度是最稀缺资源。树适合宽屏 IDE，不适合侧栏工作台。

**正确做法**：全宽列表；点条目后详情替换列表；用两行横向 chip 表达层级和类型。需要返回就一个“← 返回”。

## 3. 卡片网格冒充列表

**症状**：每条一个卡片，带图标、标签、进度条、阴影；一屏只能看 4 条，扫读效率低。

**为什么错**：卡片适合展示“少量、异构、需要视觉吸引”的内容；工作台是“大量、同构、需要快速比较”的内容。

**正确做法**：行式列表，46px 高，日期/层级/类型/标题/状态/机构六列；标题一行、摘要一行；悬停整行高亮。不要阴影和大圆角。

## 4. 编辑直接写原文

**症状**：摘要和判断直接改在 `content.md` 里；下次重新采集，原文被覆盖，判断也没了。

**为什么错**：原文是证据，批注是判断。两者生命周期不同，混在一起无法追溯。

**正确做法**：原文只读；批注写 `annotations.json`；读取时 `annotation.summary || item.summary`；保存只 `PUT /api/annotations`。

## 5. 筛选用弹层或抽屉

**症状**：点“筛选”弹出一个面板，选完再关；想看当前条件还得再点开。

**为什么错**：筛选是高频、组合、需要即时反馈的动作。弹层增加两次点击，还遮住结果。

**正确做法**：两行 chip 常驻；右侧状态/时间下拉；实时显示“共 N 条”；窄栏横向滚动，不换行。

## 6. 详情堆元数据和统计

**症状**：标题下面 12 个标签、3 个指标卡、2 个进度条，正文要滚三屏才看到。

**为什么错**：打开详情是为了读内容，不是为了看仪表盘。元数据是辅助，不是主角。

**正确做法**：标题 + 3–6 个 meta chip + 摘要 + 原文；统计只放“今日”页，且用一行数字，不用卡片。

## 7. 阅读态和编辑态混在一起

**症状**：正文看起来可编辑，点一下就变成输入框；没有保存/取消，改到一半不知道在哪。

**为什么错**：阅读需要稳定排版，编辑需要明确边界。混在一起，两种任务都做不好。

**正确做法**：明确的“编辑”按钮进入编辑态；编辑态只露出摘要、判断、状态；动作条变成“取消/保存”；`Esc` 取消，`Ctrl/Cmd+S` 保存。

## 8. Web 版假装有聊天

**症状**：浏览器版点“发送”，什么都没发生，或者报一个看不懂的错。

**为什么错**：Web 没有会话宿主，这是能力差异，不是 bug。假装有能力会让用户以为消息发出去了。

**正确做法**：`capabilities.chat` 明确声明；没有 chat 时复制到剪贴板并 toast 说明；设置页显示“会话：不支持（降级为复制）”；文档写清限制。

## 9. 数据 schema 只存在代码里

**症状**：字段名散落在 `app.js`、采集脚本、适配器里；改一个字段要全局搜索，旧数据静默失效。

**为什么错**：数据是长期资产，代码是可替换的壳。schema 不独立，换壳就丢数据。

**正确做法**：`docs/data-contract.md` 写清每个字段、类型、必填、不变量；每个 JSON 带 `schema` 版本；提供最小校验脚本；改字段先迁移。

## 10. 用真实数据做模板和截图

**症状**：示例数据里出现真实公司、人名、政策文号、内网地址；截图带着真实项目名和绝对路径。

**为什么错**：模板会公开、被 fork、被截图二次传播。真实数据一旦进入 git 历史，很难彻底删除。

**正确做法**：全部用“示例市/示例部门/示例机构/示例企业”；URL 用 `example.com`；截图前跑 `prompts/desensitize.md`；发布前 `git grep` 敏感词；不在模板里保留任何真实业务文件。

## 如果只记三条

1. **Tab 是模式，chip 是筛选。** 分类膨胀时，先加 chip。
2. **原文只读，批注可写。** 两条数据流永远不混。
3. **窄栏优先。** 420px 能用的布局，宽屏自然能用；反过来不成立。
