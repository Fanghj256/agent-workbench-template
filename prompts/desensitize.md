# 脱敏清单

公开仓库、截图、演示、给外部人看之前，跑一遍这份清单。

**原则：不要“把真名改一个字”。整条数据换成虚构的。** 真实数据一旦进入 git 历史，删除文件也不等于删除历史。

## 0. 准备

把你知道的私有词写进一个**仓库外**的文件，例如 `../private-terms.txt`，一行一个：

```text
公司名
产品名
团队名
客户名
真实人名
内部项目代号
真实域名
```

不要把这个文件提交到仓库。下面用 `-f ../private-terms.txt` 引用它。

## 1. 组织与人名

- [ ] 公司、部门、团队、客户、供应商全部替换为“示例企业甲 / 示例部门 / 示例机构”。
- [ ] 人名全部删除或替换为“示例联系人 A”。
- [ ] 邮箱、花名、IM 昵称、工号没有残留。
- [ ] 组织架构、汇报关系、内部简称没有残留。
- [ ] 文件名、目录名、变量名里没有公司/项目代号。

## 2. 政策、文件与文号

- [ ] 真实政策名称、发文字号、发布日期全部替换。
- [ ] 真实申报条件、补贴金额、截止日期不能直接照搬。
- [ ] 真实法规条款、标准编号、行业术语中的专有名称检查一遍。
- [ ] 文件标题不要用“关于……的通知”套真实标题；重新编一个明显虚构的。
- [ ] 报告里的结论、数字、案例全部重写，不要只改标题。

## 3. 数字与数据

- [ ] 营收、增长率、份额、人数、金额、面积、时长全部虚构。
- [ ] 不要用“真实数字 × 1.1”这种可反推的改法。
- [ ] 表格里的合计、同比、占比要自洽，避免一眼看出是真实报表。
- [ ] 图表截图重新生成，不要裁掉标题就发。
- [ ] 样本量、调研时间、数据来源改为“示例”。

## 4. 链接、域名、IP、邮箱

- [ ] 所有外部链接改为 `https://example.com/...`。
- [ ] 没有内网 IP、localhost 端口（模板文档里的 `127.0.0.1:8787` 是示例，可保留）。
- [ ] 没有真实邮箱、电话、地址、邮编。
- [ ] 没有企业内部系统地址、Git 地址、制品库地址。
- [ ] 二维码、短链、邀请码检查一遍。

## 5. 路径、主机名、用户名

- [ ] 没有带用户名的主目录路径（Windows 盘符 / macOS / Linux 都检查）。
- [ ] 没有真实主机名、共享盘路径、NAS 路径。
- [ ] 没有 `\\server\share`、`smb://`、`file://`。
- [ ] 文档里的命令用相对路径或 `<repo>` 占位。
- [ ] 截图里的文件管理器路径、终端提示符、IDE 标题栏检查一遍。

## 6. 令牌、密钥、配置

- [ ] 没有 API key、token、password、cookie、session id。
- [ ] 没有 `.env`、`credentials.json`、私钥、证书。
- [ ] 没有数据库连接串、OAuth client secret。
- [ ] 没有云账号 ID、项目 ID、租户 ID。
- [ ] 如果曾经提交过，**先轮换密钥**，再清理历史。

## 7. 截图与图片

- [ ] 用干净的浏览器 profile / 无痕窗口截图。
- [ ] 关闭通知、书签栏、扩展图标、下载栏。
- [ ] 标签页标题、地址栏、历史记录没有真实信息。
- [ ] 终端截图没有用户名、主机名、内网地址、命令历史。
- [ ] 图片 EXIF / 元数据已清除（`exiftool -all= image.png`）。
- [ ] 头像、二维码、文档水印、页脚检查一遍。
- [ ] 图片里的表格数字与正文一致，且都是虚构的。

## 8. 提示词、日志、注释与 git

- [ ] 提示词里没有真实业务背景、客户名、内部术语。
- [ ] 代码注释、TODO、commit message 没有真实项目名。
- [ ] 日志、错误信息、测试快照没有真实数据。
- [ ] `README`、`SETUP`、`docs/`、`prompts/` 全部过一遍。
- [ ] `.gitignore` 覆盖 `.env`、`annotations.json.bak`、`*.tmp`、`node_modules`。
- [ ] 如果仓库已提交过敏感内容：用 `git filter-repo` 重写历史，或新建一个干净仓库；轮换所有曾暴露的凭据。

## 9. 命令

在仓库根目录：

```bash
# 1) 私有词（terms 文件放在仓库外）
rg -n -i -f ../private-terms.txt .

# 2) 绝对路径
rg -n -E "[A-Za-z]:\\\\|/Users/|/home/[^/]+/" .

# 3) 内网 IP（127.0.0.1 是模板示例，可人工放行）
rg -n -E "\b(10|192\.168|172\.(1[6-9]|2[0-9]|3[01]))\.[0-9]+\.[0-9]+" .

# 4) 邮箱
rg -n -E "[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}" .

# 5) 链接（保留 example.com / creativecommons.org / opensource.org 等许可链接）
rg -n "https?://" .

# 6) 凭据关键词（有大量文档误报，逐条看）
rg -n -i "api[_-]?key|secret|password|bearer|authorization|token" .

# 7) 真实文件类型
rg --files | rg -i "\.(pdf|docx?|xlsx?|pptx?|eml|msg|db|sqlite|pem|key|p12|pfx)$"
```

Windows PowerShell 没有 `rg` 时，可以用：

```powershell
Get-ChildItem -Recurse -File | Select-String -Pattern "[A-Za-z]:\\\\|/Users/|/home/"
```

## 11. 发布流程

1. 冻结当前工作区，另存一份真实数据备份（仓库外）。
2. 用虚构数据替换 `workbench/` 全部内容。
3. 删除截图，重新用干净环境截。
4. 跑第 9 节命令；每条命中都人工确认。
5. 跑 `prompts/review-workbench.md` 的 P0。
6. 在干净目录重新 `git init`，只提交脱敏后的文件。
7. 再跑一次 `git grep`（历史 + 工作区）。
8. 发布。

## 13. 给 Agent 的脱敏提示词

```text
请按 prompts/desensitize.md 对当前仓库做脱敏审查。
1. 先列出你发现的真实组织、人名、政策、数字、链接、路径、凭据、截图风险。
2. 不要直接删除业务文件；先给出替换方案。
3. 用虚构的“示例市/示例部门/示例机构/示例企业/示例联系人”替换。
4. 跑文档里的 rg 命令，逐条确认；不要只说“看起来没问题”。
5. 最后输出：命中清单、已替换内容、仍需人工确认的项、是否可以公开。
```
